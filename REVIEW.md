## Воспроизведение гонки до исправления

На TasksProvider из `043c73b` создан browser harness, импортирующий настоящий TasksProvider. Один обработчик запускает `Promise.allSettled([remove("A"), remove("B")])`. Перехватчик имитирует контракт API: на обработке DELETE делает снимок полного списка, затем задерживает первый ответ на 400 мс, второй на 10 мс.

Команда до изменения провайдера:

```bash
npm run test:e2e -- --project=desktop --grep 'two simultaneous deletes'
```

Фактический результат: **1 failed**. Порядок ответов `DELETE:B, DELETE:A`. На сервере `[]`, ожидаемое состояние интерфейса `[]`, фактическое — массив с задачей B. Старый ответ удаления A перезаписал более свежий список после удаления B.

После исправления тот же сценарий проходит: второй HTTP-запрос ждёт завершения первого, `maxActive === 1`, обе карточки отсутствуют. Тест не пропущен, задержки и попытка конкурентного вызова сохранены. Серверную перестановку ответов предотвращает сама очередь, а не искусственное упорядочивание в тесте.

## Исправление синхронизации

Очередь создаётся один раз для каждого TasksProvider, не является глобальной между пользователями. Создание, изменение, удаление и загрузки списка используют одну цепочку Promise. Публикация снимка в React выполняется внутри операции до запуска следующего запроса. Отклонённый Promise возвращает ошибку своему потребителю, но не блокирует следующие запросы.

Загрузки из прерванного effect не публикуются. Отложенные мутации не запускаются после размонтирования провайдера, чтобы не взять токен следующего аккаунта. Такая очередь решает конкуренцию внутри одного экземпляра приложения. Она не является распределённой блокировкой для разных вкладок/внешних клиентов; повторное чтение сервера остаётся способом получить их изменения.

Пять browser-регрессий в обеих ширинах проверяют: два удаления с задержанным первым ответом; два изменения одной задачи; изменение перед удалением; удаление перед неуспешным изменением и последующая успешная операция; повторную загрузку одновременно с удалением. Тестовая HTML/React-точка входа лежит только в tests/e2e/fixtures, не подключается к приложению и не входит в production build.
