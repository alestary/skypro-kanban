# Skypro Kanban — финальная версия

React 19, Vite, React Router и styled-components. Исходный проект Александры сохранён; окончательное исправление убирает выпадающее меню и синхронизирует CRUD-запросы.

## Запуск

Рекомендуется Node.js 24 LTS и npm. Проверено на Node.js 24.19.0 / npm 11.9.0.

```bash
npm ci
npm run dev
```

Откройте адрес Vite из терминала (обычно http://localhost:5173). Для обычной работы нужны интернет и аккаунт учебного Skypro API; вход/регистрация есть в интерфейсе. Учётных данных и обязательных `.env` в проекте нет.

```bash
npm run build
npm run preview
```

При размещении на хостинге настройте возврат `index.html` для клиентских URL `/card/:id`, `/edit-card/:id` и остальных маршрутов приложения.

## Поведение и данные

- Название карточки открывает просмотр; «…» непосредственно открывает заполненное окно редактирования без выпадающего меню.
- Создание и редактирование используют один TaskForm. В окне существующей задачи доступны сохранение, отмена и удаление с подтверждением. Escape и фон закрывают окно без сохранения; во время запроса действия блокируются. Работают клавиатура и возврат фокуса.
- Доска и формы используют общий серверный список. API: `https://wedev-api.sky.pro/api`, авторизация `/user/login`, регистрация `/user/`; задачи GET/POST `/kanban`, PUT/DELETE `/kanban/:id` с Bearer.
- Приоритет имеет реальный `_id`; поле `date` — срок выполнения. После CRUD публикуется ответ сервера. Общая очередь провайдера защищает от устаревших снимков при конкурентных запросах, включая повторную загрузку.
- `data.js` — только примеры для тестов. `kanbanCards` из localStorage не используется и в сервер автоматически не переносится. ID 5 открывается, только если он действительно есть в текущем серверном наборе.
- Сессия хранится в localStorage и очищается при выходе/401. Страница 404 центрирована и доступна для неизвестных URL.

## Автоматические проверки

```bash
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
```

На Linux зависимости браузера при необходимости ставятся через `npx playwright install --with-deps chromium`. Конфигурация использует `/usr/bin/chromium`, если он установлен; для другого пути можно задать `CHROMIUM_PATH`.

Node: 9 тестов. Playwright: 18 сценариев × 2 конфигурации — desktop 1440×1000 и mobile 390×664 (эмуляция iPhone 13 в Chromium, не Safari). Playwright сам запускает Vite на порту 4173, который должен быть свободен. 5 сценариев проверяют конкуренцию запросов через отдельный тестовый entry point и настоящий TasksProvider. Остальные проверяют приложение, новое поведение «…», формы, ошибки, авторизацию и 404. По умолчанию API подменяется локальным перехватчиком, реальный сервер эти тесты не изменяют.

## Необязательная проверка реального API

Текущая версия дополнительно проверена на реальном Skypro API на отдельном QA-аккаунте. Воспроизводимый скрипт создаёт новый временный аккаунт, проверяет CRUD/refresh/выход на обеих ширинах и удаляет свои карточки. Он не использует личные аккаунты. Пароль и токен генерируются/хранятся только в памяти, не выводятся в отчёт. Удаление самой QA-учётной записи API проекта не предоставляет.

В одном терминале запустите приложение:

```bash
npm run dev -- --host 127.0.0.1 --port 4174 --strictPort
```

В другом терминале:

```bash
node --use-env-proxy scripts/check-live-api.mjs --run
```

Скрипт явно пересылает настоящие запросы браузера через Node fetch к Skypro с сохранением TLS-проверки и сетевого прокси среды; ответы и данные не имитируются. Для другого URL сервера можно задать `KANBAN_BASE_URL`; для папки снимков и безопасного JSON-отчёта — `KANBAN_QA_OUTPUT`. По умолчанию результат попадает в игнорируемую `test-results/live-api/`. Без `--run` скрипт отказывается создавать аккаунт.
