## Три замечания преподавателя

### 1. Просмотр существующей задачи

Изначальная причина — доска читала data.js, а просмотр/формы/удаление читали независимый localStorage. На первом этапе устранено разделение источников: доска и маршруты используют общий список Skypro API, `_id` нормализуется в строку и имеет приоритет над legacy `id`. Нет специальных условий для 5, подмешивания примеров или фиктивной карточки.

Финальная версия сохраняет это решение. Проверены задачи 5/1/3/6 в контролируемом серверном наборе, непрозрачный `_id`, отличный от локального 5, правильные поля, прямые ссылки и отсутствующий ID. В реальном новом QA-аккаунте сервер выдал собственные `_id`: открытие созданных задач и поля проверены по ним. Реальное существование ID 5 в личном аккаунте Александры не проверялось и не предполагается.

### 2. «…» и окно работы с задачей — P1

В предыдущем исправлении оставалось выпадающее меню; оно противоречило уточнённому требованию текущего задания. Теперь Card.jsx содержит обычную кнопку «…», которая сразу открывает `/edit-card/:id` с заполненной TaskForm. Компонент выпадающего меню удалён. Нет действий menuitem и промежуточного списка «Открыть/Редактировать/Удалить».

TaskForm используется и для создания, и для редактирования, поэтому поля, сетка, категории, размеры и мобильное поведение совпадают. В редактировании добавлена кнопка удаления с подтверждением; пустой ID/отсутствующая запись не создают фиктивную форму. Сохранение делает PUT того же ID, создание — POST с серверным ID. Сохранены валидация названия/категории/статуса/даты, вывод ошибки с сохранением полей, блокировка повторной отправки и закрытия во время запроса.

Отмена, Escape и фон не сохраняют изменения. Modal удерживает фокус и возвращает его на кнопку карточки. Enter и Space открывают форму, Tab/Shift+Tab остаются внутри окна. Название карточки по-прежнему ведёт на страницу просмотра с редактированием/удалением. Ни одно удаление не использует reload документа.

Старые browser-тесты действий выпадающего меню заменены проверками прямого открытия формы, её значений и клавиатуры. В тесте дополнительно проверяется отсутствие role=menu. Адаптивность и геометрия окна проверены на обеих ширинах; снимки реального API просмотрены. Сравнение именно с исходным макетом невозможно без него.

### 3. Страница 404

Сохранено центрирование grid/place-items по горизонтали и вертикали на высоту viewport (vh/dvh), адаптивные размеры и React Router Link на главную. Проверены неизвестный вложенный URL, геометрический центр блока (отклонение < 2 px) и ссылка возврата на обеих ширинах. В текущем wildcard-layout Header отсутствует, поэтому высота шапки не добавляется к viewport. Защищённые маршруты и вход/выход продолжают работать.

## Гонка CRUD — P2

Исходная ошибка воспроизведена **до изменения TasksProvider** настоящим браузером и отдельным harness, импортирующим реальный провайдер. Одновременно вызваны remove(A)/remove(B). Первый ответ удерживался 400 мс, второй — 10 мс; ответы содержали снимки списка на момент обработки запросов. При порядке ответов `DELETE:B, DELETE:A` тест упал: на сервере `[]`, в UI вернулась B. Команда, фактический результат ошибки и объяснение — в REVIEW.md.

Добавлена очередь requestQueue.js, единственная для данного экземпляра TasksProvider/сессии. Она сериализует **все** create/update/remove и чтения списка, а не только кнопки одной карточки. Ответ публикуется до начала следующей операции. Ошибка возвращается вызывающему коду, но очередь продолжает работать. Отменённые чтения не публикуются; отложенные мутации не запускаются после размонтирования провайдера с новым токеном другого пользователя.

Это предотвращает перестановку снимков: второй запрос не может получить и опубликовать ответ раньше первого. Автоматически проверены два удаления, два обновления одной задачи, обновление перед удалением, удаление перед ошибочным обновлением и следующей успешной операцией, а также загрузка списка одновременно с удалением. Во всех mutation-сценариях проверяется maxActive=1. После исправления тот же регрессионный тест с задержанным первым ответом проходит. Очередь ограничена текущим провайдером: синхронизацию между разными вкладками/клиентами или распределённые серверные блокировки она не реализует.

## Реальный Skypro API

Создан отдельный новый QA-аккаунт с произвольным логином в example.test и случайным паролем. Личные аккаунты/данные не использовались. Пароль и токен оставались только в памяти процесса/сессии браузера, не выводились и не входят в проект/ZIP.

Реальные browser-проверки пройдены на desktop и mobile:

- регистрация (один аккаунт для двух прогонов) и вход;
- создание своей временной карточки, получение настоящего `_id`;
- просмотр и проверка полей;
- заполненная форма, изменение названия, описания, категории, статуса и даты;
- PUT по существующему ID без дубликата;
- refresh и повторный просмотр сохранённых сервером изменений;
- прямое открытие через «…», отмена удаления и подтверждённое удаление;
- refresh с пустой доской после удаления своих карточек;
- выход, очистка токена, защита маршрута после выхода;
- отсутствие pageerror и console.error в обоих прогонах.

Ответы реального сервера: регистрация/login — 201, GET задач — 200, POST/PUT/DELETE — 201. Из-за сетевого прокси Cloud запросы браузера пересылались к настоящему HTTPS API через Node fetch с включённой TLS-проверкой. Данные/ответы не заменялись тестовыми. Это проверяет реальный CRUD и persistence; прямой сетевой путь обычного пользовательского браузера вне Cloud отдельно не проверялся.

Обе временные карточки удалены. Сам новый QA-аккаунт остаётся на учебном сервере: поддерживаемый API проекта не предоставляет удаление учётной записи. Логин/пароль не сохранялись. Безопасный JSON-протокол и снимки локально находятся в `/workspace/qa-final`; в ZIP не включены. Для повторения добавлен явно запускаемый `scripts/check-live-api.mjs --run`, инструкция — в README. Обычные npm tests не обращаются к реальному API.

Рядом передаётся `/workspace/shared/downloads/kanban-skypro-final.patch` — полный diff относительно remote develop `3e423e1`, включая первый этап исправлений. Если ветка Александры остаётся на этом состоянии, перенос выполняется в её чистом клоне:

```bash
git switch develop
git pull --ff-only origin develop
git status --short
git apply --check /path/to/kanban-skypro-final.patch
git apply --index /path/to/kanban-skypro-final.patch
npm ci
npm run build
npm run lint
npm test
npm run test:e2e
git commit -m "Fix Kanban task modal and synchronize CRUD requests"
```

Перед apply рабочее дерево должно быть чистым. Для browser-проверки предварительно установите Chromium по README. Если ветка уже получила другие изменения и apply --check сообщает конфликт, нельзя применять патч вслепую; нужно перенести изменения с учётом актуального diff. После обычного push в develop существующий PR № 3 обновится автоматически; новый PR/merge не требуется. ZIP также позволяет запустить проект без git, но для обновления PR удобнее проверенный консолидированный патч.

Архив содержит 77 файлов. Проверены CRC, распаковка и побайтное совпадение с проектом. После контрольного прогона обновлён только этот отчёт; исходный код финального ZIP сверяется с прошедшей чистые проверки копией. Консолидированный патч применён к отдельному чистому worktree origin/develop, получено полное совпадение дерева файлов.

У Cloud-сессии нет отдельного доступного инструмента публикации файла во внешний download URL. Предоставляется фактический локальный путь и файловая ссылка; скачивание из пользовательского интерфейса не подтверждено. Не утверждается, что архив уже опубликован на GitHub или внешнем хостинге.
